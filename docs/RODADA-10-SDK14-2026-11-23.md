## 4. Severed Chains — bloqueio concreto apesar de v7 Java

Foi baixado e inspecionado **Severed_Chains_Windows.zip** da release release-3.0.0: **131.446.655 bytes**, SHA-256 **164716cba1899cadf834506636de8da56721d695457c3b53c93c533999ef9bb4**. Arquivo com 769 entradas (inclui updater.jar, lod-game-ab5dfe5ba6d4c07464a2f0e67985b9e77e2f7bdb.jar e dezenas de libs/). Ambos os JARs têm META-INF/MANIFEST.MF com Main-Class, mas a classe de jogo usa major version **69 (Java 25)**.

O launcher oficial launch.bat exige um JDK 25 e inicia Java com **-cp incluindo várias bibliotecas** e argumentos JVM específicos. O SDK v7 oferece apenas java_launcher com runtime java-21, invocando **-jar** sem argumentos extras. Usar -jar para o game JAR ignora o classpath externo exigido e Java 21 não executa bytecode Java 25. O updater.jar não é comprovadamente um entrypoint equivalente ao launcher do jogo. Logo, **não criar receita v7** apenas com esse JAR.

Solicitação concreta ao Codex: contrato reutilizável de launcher Java com JDK 25+ verificado e **classpath declarativo formado exclusivamente por caminhos de release verificados e lista fechada de opções JVM aprovadas**, sem permitir BAT ou string de comando arbitrária, com staging, validação de libs, consentimento, timeout e teste de boot real. A equipe upstream também pode publicar um JAR executável fat com todas as dependências e exigências documentadas.

## 5. Project Picori, WipeOut e Phase Distorter

- **Project Picori:** suporte a tar.gz v7 existe, mas catálogo oficial aponta perfil https://github.com/999sian; upstream operacional conhecido 999sian/tmc v0.9.6 publica tar.gz. É obrigatório corrigir a identidade no AllFix-Repo antes de criar receita; não foi alterado.
- **WipeOut Phantom Edition:** upstream pede BIN/CUE de 9 faixas da edição USA, mas não publica hashes/tamanhos reproduzíveis para cada arquivo. V7 valida referências CUE, porém a lista verificável de entradas não pode ser preenchida com valores presumidos. Receita v5 preservada.
- **Phase Distorter:** o port importa ROM própria e gera earthbound.ebpak ou mother2.ebpak em %APPDATA%/ebsrc/EarthBoundCpp. V7 passou a suportar perfil multinível, mas importar a ROM por simples cópia **não executa o extrator oficial**. A verificação passiva de first_run_files não permite alternativa OR para US/JP com critérios fortes sem restringir o público. Receita v5 preservada.
- **Instaladores e builds:** perfis installer_profile/build_profile desativados no SDK 1.4.0; nenhum exec/script arbitrário foi criado.

## 7. Testes e integridade

- JSON Schema Draft 2020-12: schemas v6 e v7 importados do handoff e validados com os 5 exemplos sintéticos do SDK.
- Validador GetAll estendido a v6/v7 **sem remover os testes v3/v5**; inclui assets com hash/tamanho e restrições de scripts, java_launcher seguro, arcade_romset com tamanho/CRC32, faixas CUE/BIN e perfis.
- Testes novos positivos/negativos: payload exe proibido, asset SHA/tamanho inválido, JAR não declarado ou com path traversal, perfil inseguro, romset adulterado/ausente, CUE sem BIN, perfis installer/build não aprovados.
- Parser real compilado AllFix.dll 1.4.0: **91/91 index e receitas parseados**. Harness .NET dedicado com **70 verificações**, incluindo arquivo sintético ASCII 123456789, validação nativa CRC32 CBF43926, rejeição de corrupção de mesmo tamanho e ROM ausente. Nenhum jogo foi executado.
- Validação de arquivos oficiais: AutoTMC, Cannonball, Zelda3, SMW e Severed Chains baixados e inspecionados, tamanhos e hashes anotados. Os hashes do index.json são SHA-256 dos bytes exatos de cada JSON.
- **Sem testes com ROMs comerciais ou primeiro boot.** As 90 receitas não homologadas continuam experimentais. A única validated histórica permanece SM64 Coop Deluxe v1.5.1.
